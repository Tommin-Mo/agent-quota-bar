# 现有项目调研与方案评估

> 目标：在 macOS 顶部菜单栏统一查看 **OpenCode、ChatGPT/Codex、WorkBuddy 积分、Trae 积分、DeepSeek 余额**。
> 本文是先做的调研与取舍记录，结论对应本仓库的实现（`agent-quota-bar/`）。
> 实测时间：2026-10-20，环境 macOS 27 / Apple Silicon / Node 24。

## TL;DR

1. **没有开箱即用的项目能覆盖这 5 家。** 最接近的是 [CodexBar](https://github.com/steipete/CodexBar)（MIT，106 个 provider），原生支持 Codex、OpenCode、DeepSeek，但**没有 Trae 和 WorkBuddy**。
2. **Trae / WorkBuddy 的接口知识不在菜单栏项目里**，而是散落在两个国内工具：[dsh-trae-api](https://github.com/Wang-JQ77/dsh-trae-api)（Trae 登录态解密）和 [buddyToken](https://github.com/CaoDonald/buddyToken)（WorkBuddy 积分账单接口）。
3. 三条路：
   - **A. 直接用 CodexBar**：10 分钟装好，覆盖 3/5；
   - **B. Fork CodexBar 加两个 provider**：长期最优雅，但要完整 Xcode + 读一个很大的 Swift 工程；
   - **C. 自建轻量壳（本仓库）**：Swift 菜单栏壳 + Node collector，5/5 全覆盖，约 1 天工作量，已实测可用。
4. 本机实测五家接口均能取到数据；具体账号数值和到期时间不写入仓库。

## 需求拆解：五家的口径完全不同

| 服务 | 剩余额度的真实含义 | 数据来源类型 |
| --- | --- | --- |
| Codex / ChatGPT | 5 小时 / 每周窗口的已用百分比 + 重置时间，另有积分 | OAuth access token → 官方 web 接口 |
| DeepSeek | 账户余额（充值 + 赠金），按量计费 | 官方 API Key → 官方余额接口 |
| OpenCode | 两套东西：**Zen 预付余额**（USD）或 **Go 订阅**的 5h/周/月窗口 | 浏览器 Console Cookie 或 Go API Key |
| Trae | 套餐内的快速/慢速请求次数、积分，以及套餐到期日 | 本机 IDE 登录态（加密）→ 上游接口 |
| WorkBuddy | 积分余额（多个套餐包，各有到期时间） | 本机桌面端快照（新版加密）→ web 账单接口 |

所以这本质上不是“读五个 API”，而是**五个不同来源的 adapter**：OAuth、API Key、浏览器 Cookie、本机加密文件、本机明文快照。

## 现有项目盘点

### 1. CodexBar（steipete）— 最完整的现成答案

- 仓库：https://github.com/steipete/CodexBar，MIT，macOS 14+，也有 Linux 桌面版。
- 形态：菜单栏 App（每个 provider 一个 status item，可合并图标）+ CLI（`codexbar serve`，第三方 SketchyBar / Noctalia 插件都基于它）。
- 覆盖：**106 个 provider**，其中和本次相关的：
  - **Codex**：OAuth API / CLI RPC / OpenAI web dashboard；
  - **OpenCode**：`opencode.ai` 浏览器 Cookie + Console JSON（`/console/api/orgs`、`/go/status`、`/billing/status`）；
  - **OpenCode Go**：`/zen/go/v1/usage` + 本地 SQLite 成本历史；
  - **DeepSeek**：API Key 查余额（含赠金/充值拆分）。
- 优点：成熟、有签名发布、Homebrew cask、错误处理和降级做得很细（cookie 导入、刷新、数据置信度）。
- 缺点：**没有 Trae、没有 WorkBuddy**；Swift 工程很大，加 provider 需要 fork + Xcode，不适合“今天就要用”。
- 结论：如果只缺 1 家，直接用它 + 手动看另一个最划算；缺 2 家且都是国内产品，就不划算了。

### 2. simple-usage（VVnx）— 最小可改的 Codex/Claude 菜单栏

- 仓库：https://github.com/VVnx/simple-usage，MIT。
- 原生 Swift + AppKit，一个菜单栏，只做 Claude Code / Codex 的 5 小时 + 每周百分比、重置倒计时。
- 关键实现：读 `~/.codex/auth.json`，请求 `https://chatgpt.com/backend-api/wham/usage`，请求头带 `Authorization: Bearer <access_token>` 和 `chatgpt-account-id`。
- 适合：只想看 Codex/Claude，或者想拿一份 500 行以内的 Swift 菜单栏骨架来改。
- 不适合：需要多 provider 聚合。

### 3. ai-usage-monitor（stavrop）

- 仓库：https://github.com/stavrop/ai-usage-monitor。
- 菜单栏显示 Claude 和 ChatGPT 的用量上限，形态和 simple-usage 接近。
- 仓库未标注 License（README 没有，LICENSE 拉取为空），**参考思路可以，直接复用代码前要先确认授权**。

### 4. ccusage（ryoppippi）

- CLI，读取 Claude Code / Codex 的本地 session 日志，统计 token 与费用（`ccusage blocks --live` 等）。
- 是“花了多少”的工具，不是“还剩多少”的工具；可以作为本地成本补充，但解决不了余额/窗口问题。
- License：MIT（monorepo）。

### 5. opencode-usage-left

- npm：`opencode-usage-left`，MIT，OpenCode TUI 插件。
- 价值：把 OpenCode 的 Zen/Go 适配讲得最清楚——**没有公开余额接口**，需要用 `workspaceId + authCookie` 去 `https://opencode.ai/workspace/<id>/billing` 或 `/go` 页面抓 `balance:` / `usagePercent:`。
- 和 CodexBar 的 Console JSON 方案相比，HTML 抓取更脆；我们在实现里选了 Console JSON（见下）。

### 6. buddyToken（CaoDonald / akexin fork）

- 仓库：https://github.com/CaoDonald/buddyToken，MIT，纯本地 Node 看板（Windows 为主）。
- 价值：目前对 **WorkBuddy / CodeBuddy 积分**研究最深的开源项目，包含：
  - 账号发现：`%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\*.info`（macOS 对应 `~/Library/Application Support/CodeBuddyExtension/Data/Public/auth/`）；
  - 积分接口：`POST https://www.workbuddy.cn/billing/meter/get-user-resource-summary`，`Authorization: Bearer <accessToken>`、`X-User-Id`、`X-Client-Platform: web`；
  - 套餐明细：`get-user-resource-paid-packages` / `get-user-resource-free-packages`；
  - **新版 5.6.2+ 把快照里的 accessToken 用 `$wbEncrypted` 信封（AES-256-GCM）加密**，密钥来自构建期 secret，项目里也需要单独取证的 `wb-field-key.json` 才能解。
- 结论：接口可以直接复用；**新版本机 token 不能离线解密**，这是 WorkBuddy 自动化的硬限制。

### 7. dsh-trae-api（Wang-JQ77，@hajilongshi fork）

- 仓库：https://github.com/Wang-JQ77/dsh-trae-api，MIT；npm 包 `@hajilongshi/dsh-trae-api`。
- 价值：不是额度 UI，而是 Trae 的本地 API 代理。但它完整解决了 **Trae 登录态解密**：
  - 读 `~/Library/Application Support/Trae CN/User/globalStorage/storage.json`；
  - `iCubeAuthInfo://icube.cloudide` 是 `tc` 格式：6B header + 32B random + AES-128-CBC 密文，SHA-512 校验；
  - 解出 `token / refreshToken / host`（实测 host 为 `https://api.trae.cn`）。
- 我们用它的解密算法（保留 MIT 署名，见 `collector/trae-crypto.js`）再配合 Trae 自己的额度接口，就拿到了积分/套餐数据。

## 关键接口（本机实测）

### Codex / ChatGPT
```
GET https://chatgpt.com/backend-api/wham/usage
Authorization: Bearer <access_token>       # 来自 ~/.codex/auth.json
chatgpt-account-id: <account_id>
User-Agent: codex-cli
```
返回 `plan_type`、`rate_limit.primary_window.used_percent / limit_window_seconds / reset_at`、`credits.balance`。
本仓库只读取 `rate_limit` 和 `credits` 字段，不刷新 token、不写回 Codex 登录态。

> 国内网络需要代理；`~/.codex/auth.json` 里的 access_token 会过期。本工具**只读不刷新**——refresh token 是一次性的，抢着刷新会和 Codex CLI 互相踢掉登录态。

### DeepSeek
```
GET https://api.deepseek.com/user/balance
Authorization: Bearer <api_key>
```
返回 `balance_infos[0].total_balance / granted_balance / topped_up_balance`，官方稳定接口。

### OpenCode
两条路：
```
# Go 订阅（5h / weekly / monthly 窗口）
GET https://opencode.ai/zen/go/v1/usage
Authorization: Bearer <OPENCODE_API_KEY>

# Zen 预付余额（需要浏览器 Console 会话）
GET https://opencode.ai/console/api/orgs              # 列 workspace
GET https://opencode.ai/console/api/billing/status    # x-org-id + Cookie: __Host-console_session
GET https://opencode.ai/console/api/go/status         # 订阅窗口
```
`billing/status` 的 `balanceMicroCents` 除以 1e8 即美元余额。OpenCode 官方 issue（#44189）明确说过 Zen 余额没有 API Key 接口，只能用 console 会话。

### Trae
```
POST https://api.trae.cn/trae/api/v1/pay/ide_user_ent_usage
Authorization: Cloud-IDE-JWT <token>
Content-Type: application/json

{"require_usage": true, "req_source": "IDE"}
```
返回 `user_entitlement_pack_list[]`：每包的 `quota`（快速/慢速请求上限）、`usage`（已用）、`entitlement_base_info.end_time`。
注意：v2 路径本机返回 400，v1 可用；token 从 Trae CN 的 `storage.json` 解密（`tc` 格式）。

### WorkBuddy
```
POST https://www.workbuddy.cn/billing/meter/get-user-resource-summary
Authorization: Bearer <accessToken>
X-User-Id: <uid>
X-Client-Platform: web

{}
```
返回 `data.Packages[]`，积分字段兼容 `CycleCapacitySizePrecise` / `CycleCapacityRemainPrecise` 等命名。
凭据来自 `~/Library/Application Support/CodeBuddyExtension/Data/Public/auth/workbuddy-desktop.info`；新版字段是加密信封。

## 三条路线的取舍

| 方案 | 覆盖 | 上手成本 | 维护成本 | 适合 |
| --- | --- | --- | --- | --- |
| A. 直接用 CodexBar | 3/5 | 10 分钟 | 官方更新 | 能接受 Trae/WorkBuddy 另看 |
| B. Fork CodexBar 加 provider | 5/5 | 1–2 天（需 Xcode） | 跟随上游 merge，长期偏高 | 想长期维护/开源，追求原生体验 |
| **C. 自建薄壳（本仓库）** | **5/5** | **半天到 1 天** | 接口变了改一个 JS 函数 | 个人自用，快速覆盖全部 5 家 |

选 C 的额外理由：

- 五家的鉴权方式差异太大，用 **Node collector 统一适配**比在 Swift 里写五套 OAuth/Cookie/解密逻辑快得多；
- UI 只需要一个状态栏文字 + 一个 popover，AppKit 足够，不依赖 Xcode；
- 每家 provider 是独立的 `collect*` 函数，新增一家约 40 行；出错只影响自己那一行。

## 风险与边界

1. **全部是“自己的账号、只读”**：不绕过付费、不共享 token、不复用别人的 cookie。配置文件在本机 `~/.config/agent-quota/config.json`（600）。
2. **非官方接口**：ChatGPT/WorkBuddy/Trae 的接口都未公开承诺稳定，字段或域名可能变；变的代价是改 collector 里对应函数。
3. **Codex**：需要代理；access_token 过期会显示“登录态已过期”，重开 ChatGPT/Codex 即可。工具不写 `auth.json`。
4. **OpenCode**：Zen 余额必须用 console cookie（会随浏览器会话过期）；Go 额度优先用 API Key。
5. **WorkBuddy**：新版桌面端把 token 加密了，无法像旧版一样直接读明文。当前策略是“旧明文快照自动发现 + 手动 token”。`/v2/plugin/auth/token/refresh` 可以刷新，但 refresh token 单次有效，和桌面端抢会互相失效，**不建议自动做**。
6. **Trae**：解密依赖客户端实现，Trae 升级可能改加密格式；`tc` 格式和盐值来自 MIT 项目的逆向结果。
7. **合规**：仅本机、仅本人账号、仅读取。对外分发前应再确认各家的 ToS 对“第三方读取自己账号用量”的态度。

## 如果要继续演进

1. 把 Trae 和 WorkBuddy 两个 provider 抽成 CodexBar 的 PR（长期最干净，但要读它的 provider 抽象和 Xcode 工程）。
2. OpenCode 增加“自动从浏览器导入 cookie”（CodexBar 已有成熟实现可参考），减少手动粘贴。
3. WorkBuddy 等官方开放接口，或改成读取桌面端解密后的内存/本地明文缓存。
4. 增加“额度预警通知”（菜单栏变红 + 系统通知），这是比看数字更高频的需求。
